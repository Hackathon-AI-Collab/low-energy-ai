* Vision & Mission

** Vision
To create a decentralized, resilient, and low-power AI platform that delivers critical knowledge and communication capabilities to individuals in the world's most challenging environments, including disaster zones and conflict areas.

** Mission
To build a mobile-first application using React Native that provides distributed AI processing through Bluetooth Low Energy (BLE) connectivity, enabling mobile devices to access powerful AI models running on nearby computers while maintaining low power consumption and operational effectiveness in disconnected settings.

* The Problem
In crisis zones, traditional connectivity infrastructure is often the first to fail. This isolates communities and first responders from critical information and AI-powered assistance when they need it most. Without a reliable way to connect people with knowledge and AI resources, response efforts are hampered, and lives are put at risk.

* Our Solution: The Rufaydah AI Mesh Platform
The Rufaydah platform is a decentralized, resilient, and low-power AI ecosystem designed for the world's most challenging environments. It establishes a peer-to-peer mesh network of devices that can share knowledge and access AI without relying on centralized infrastructure.

The core components are:
- *Rufi Devices*: Local AI processing nodes running LLM models on cross-platform devices (Android, iOS, Laptops).
- *RAG System*: A Retrieval-Augmented Generation pipeline provides context-aware responses from a local and shared knowledge base of critical documents.
- *Bluetooth Mesh*: Peer-to-peer connectivity between Rufi devices enables a low-signature, infrastructure-free communication network.

* Core Use Cases

** Primary (Distributed AI Processing)
1. *Emergency Response AI:* Provide immediate, authoritative medical guidance (e.g., TCCC) to medics and first responders through distributed AI processing.
2. *Field Intelligence:* Offer real-time analysis and procedural guidance for complex operations using powerful AI models.
3. *Technical Information:* Act as an interactive manual for equipment, pharmaceuticals, and other technical domains with AI-powered responses.

** Secondary (System & Network)
4. *Distributed Computing:* Enable mobile devices to leverage powerful AI models running on nearby computers through BLE connectivity.
5. *Low-Signature Communication:* Use BLE for device discovery and connection management to reduce detection risk compared to Wi-Fi or cellular.

* System Architecture

The Rufaydah platform is designed as a modular React Native application with distributed AI capabilities. The architecture consists of three main layers: the *Application Layer*, the *Distributed AI Layer*, and the *BLE Communication Layer*.

** Application Layer (UI/UX)

- *Framework:* React Native with TypeScript
- *UI Components:* Clean, intuitive chat-based interface with device management
  - =ChatScreen=: Main interface for querying distributed AI models
  - =SettingsScreen=: Device connection management and configuration
  - =DeviceSelectionCard=: BLE device discovery and connection interface
- *State Management:* Global state management for AI processing status, device connections, and user settings

** Distributed AI Layer

This layer handles distributed AI processing through BLE-connected workers.

- *Distributed LLM Service:*
  - *Primary Model:* phi3:mini running on remote computers via Ollama
  - *Connection:* HTTP API calls to Ollama instances on worker devices
  - *Fallback:* Local RAG system when no distributed workers are available
- *RAG (Retrieval-Augmented Generation) Pipeline:*
  1. *Query Processing:* User queries are sent to connected AI workers
  2. *Context Retrieval:* Local knowledge base provides relevant context
  3. *Distributed Inference:* Remote AI models process queries with context
  4. *Response Streaming:* AI responses are streamed back to the mobile device

** BLE Communication Layer

This layer manages device discovery and connection management.

- *BLE Service:*
  - *Service UUID:* Custom BLE service for device discovery
  - *Characteristics:* Device information, connection status, and query routing
- *Device Management:*
  - *Advertising:* Worker devices advertise their AI model capabilities
  - *Scanning:* Mobile devices scan for available AI workers
  - *Connection:* Persistent BLE connections for device management

* Architecture Benefits

- *Low Power:* BLE uses minimal power compared to Wi-Fi
- *Low Detection:* BLE has minimal RF signature
- *Distributed:* Leverages nearby computational resources
- *Resilient:* Works offline with local knowledge base
- *Scalable:* Multiple workers can serve multiple devices

* Technology Stack
The platform has evolved to optimize for performance and efficiency on resource-constrained devices.

** LLM Runtime
The system initially used an ONNX-based runtime, which suffered from poor performance on mobile. It was migrated to *Llama.rn*, which offers significantly better performance and faster inference times. The next iteration plans to use *MLC-LLM* for further speed and optimization gains.

** Vector Storage & Search
The RAG system's initial in-memory vector search (Voy) was too memory-intensive for mobile devices. The current implementation uses a combination of *SQL-Vec* and *Op-SQLite*, which provides an efficient and optimized solution for vector storage and local embedding generation on mobile devices.

* Technical Implementation

** Device Configuration

- *Worker Devices/Rufis:* Computers running Ollama with AI models or Mobile with Rufaydah App
- *Consumer Devices:* Mobile phones running the Rufaydah app
- *Network:* BLE for discovery, HTTP for AI queries

* Bluetooth Mesh Network
The mesh network allows for automatic discovery and resource sharing between Rufi devices.

- *Rufi Discovery*: Automatically detects nearby AI-enabled devices.
- *Dual Role Support*: Each Rufi can act as a Producer (serving an LLM and documents) or a Consumer (querying the network).
- *Architecture*:
#+BEGIN_SRC
Rufi Device A (Producer) <--> Rufi Device B (Consumer)
       |                           |
  LLM + Docs                  Query Interface
       |                           |
  Bluetooth LE <---------------> Bluetooth LE
#+END_SRC

* Getting Started

** Prerequisites
- Node.js 18+ and npm
- React Native development environment
- Python 3.8+ with pip
- Ollama installed on worker devices or App on two devices
- Android/iOS development tools

** Quick Start
** Worker Setup (Python)

#+BEGIN_SRC bash
# Install dependencies
pip install -r requirements.txt

# Run BLE advertiser
python3 scripts/bluetoothctl-advertiser.py --device-name "Rufaydah-Phi3"

# Run AI worker server
python3 scripts/leai-ble-server.py --model phi3 --device-name "Rufaydah Provider" --port 11434
#+END_SRC

** Mobile App Setup

#+BEGIN_SRC bash

# Run on Android
